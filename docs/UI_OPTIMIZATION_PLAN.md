# KeBaiPay UI/UX 优化任务清单（0.3.0 规划稿）

> 对标参照：**Stripe Dashboard**（信息密度与克制）、**Wise**（转账流程与费率透明）、**Revolut**（钱包卡片式首页）、**支付宝开放平台**（商户后台导航）、**Element Plus 官方规范**（组件默认行为）
> 使用方式：每项含【现状 → 目标 → 验收标准 → 预估工作量（S=0.5天 / M=1天 / L=2-3天）】。按 P0→P3 顺序执行，P0 未完成不进 P1。
> 执行分支：`feat/ui-0.3.0`；涉及四端（web-admin / web / web-h5 / public SPA），全部走 design-system.css 统一令牌

---

## P0 设计基础层（先行，1 周内）

### P0-1 设计令牌补全（design-system.css 三端同步）
- 【现状】已有品牌色/圆角/阴影/动效变量；缺间距体系、字号阶梯令牌、语义色变量（成功/警告/危险仅 EP 默认映射）
- 【目标】新增 `--kb-space-1~8`（4/8/12/16/24/32/48/64px）、`--kb-font-*`（caption 12/body 14/body-strong 14/600/title 16/600/page-title 20/700）、`--kb-radius-card 16px`/`--kb-radius-btn 10px`
- 【验收】三端 CSS 变量完全一致（diff 对比）；所有新样式只允许引用令牌
- 工作量 M

### P0-2 按钮体系规范化（全端扫描替换）
- 【现状】按钮混用 primary/default/text/link；危险操作（冻结用户、删除渠道、驳回）有的用 danger 有的用 default
- 【目标】语义固化：**主行动每屏至多 1 个 primary**；危险操作一律 `type="danger" plain` + 二次确认弹窗（ElMessageBox.confirm，文案含不可逆提示）；表格内行操作统一 `link type="primary"`；加载态一律 `:loading`
- 【验收】全端 `el-button` 逐个 grep 审查表（附在 PR 描述）；危险操作 100% 有 confirm
- 工作量 M

### P0-3 数字与金额展示统一
- 【现状】金额已 tabular-nums；但部分页面金额无千分位（如 ¥10066.66 → ¥10,066.66）
- 【目标】新增 `fmtMoney(fen)` 通用函数（千分位 + 两位小数 + 负号红显）；四端所有金额渲染统一走它
- 【验收】四端 grep 所有 `amountYuan|fenToYuan` 渲染点全部替换；视觉抽查
- 工作量 S

### P0-4 响应式断点落地
- 【现状】admin/portal 侧边栏固定 224px，窄屏（<1024）挤压；H5 移动端良好；表格列在窄屏横向溢出无提示
- 【目标】断点：<1280 侧边栏收窄为图标模式（el-menu collapse）；<992 汉堡抽屉；表格容器加 `overflow-x:auto` + 列最小宽；H5 在 768-1024 平板宽度居中限宽 480px
- 【验收】1440/1280/1024/768/390 五档宽度截图走查无横向滚动条（表格除外）、无遮挡
- 工作量 L

### P0-5 空状态/加载态/错误态三态统一组件
- 【现状】空状态文案不统一（"暂无数据"/"暂无账单"/"暂无待审核实名"各写各的）；错误靠 ElMessage toast 一闪而过
- 【目标】封装 `<KbEmpty text description action?>`（含插画占位）、`<KbErrorState @retry>`（含重试按钮）；列表页统一替换
- 【验收】所有列表页三态可见（mock 数据演示）；错误态必带重试
- 工作量 M

## P1 管理后台 Admin（逐页，2 周）

### P1-1 登录页
- 现状：可用但品牌感弱；无"大写锁定提醒"、无回车提交
- 目标：回车提交 ✓（验证）；大写锁定检测提示；登录中按钮 loading+禁用；错误提示改为表单内联而非仅 toast
- 验收：回车可登录；CapsLock 开启时输入框旁出现提示；错误消息内联红字
- 工作量 S

### P1-2 数据概览
- 现状：指标卡文字堆叠，无趋势、无跳转锚点
- 目标：对齐 Stripe 风格——指标卡增加环比箭头（↑↓%）、迷你趋势图（近 7 日 sparkline，ECharts 按需引入）、点击卡片跳转对应列表页并带上筛选条件
- 验收：5 张指标卡均可点击跳转且带状态过滤
- 工作量 L

### P1-3 用户管理
- 现状：表格 7 列平铺；搜索只有一个关键字框
- 目标：①关键字搜索支持昵称/手机号/邮箱（后端已支持 keyword）；②行点击展开用户详情抽屉（含实名信息/账户/最近账单 tab）；③冻结/解冻按钮后置到详情抽屉，表格只保留状态标签；④新增「风控等级」列
- 验收：从搜索到冻结操作全流程 3 次点击内完成；详情抽屉数据正确
- 工作量 M

### P1-4 商户管理
- 现状：审核操作按钮直接放行/驳回
- 目标：通过前弹出确认（展示费率/限额摘要）；驳回强制填原因（表单校验）；增加商户详情抽屉（应用列表/费率修改入口）
- 验收：驳回不出原因无法提交
- 工作量 M

### P1-5 实名审核
- 现状：证件号脱敏展示已好；缺对比视图
- 目标：审核抽屉内并排展示「姓名+证件号」与用户填写一致性高亮；通过/驳回快捷键（P 进入通过、X 驳回）
- 验收：单条审核 ≤ 10 秒
- 工作量 S

### P1-6 渠道配置
- 现状：凭据 JSON 编辑是文本框；错误只能保存后发现
- 目标：①JSON 编辑器带语法高亮（CodeMirror 按需）；②保存前本地校验 JSON 合法性；③「测试」按钮接入后端测试端点并展示结果面板；④启用开关用 el-switch 即时生效
- 验收：非法 JSON 无法保存；测试结果面板展示成功/失败详情
- 工作量 M

### P1-7 提现审核
- 现状：通过/拒绝按钮直接可用
- 目标：通过前展示用户余额/冻结明细 + 二次确认（代付不可逆）；批量勾选审核（后端如无批量端点则列 P2）；驳回原因必填
- 验收：通过操作需 2 次确认；驳回必填原因
- 工作量 M

### P1-8 支付订单
- 现状：列表 + 筛选
- 目标：①行点击订单详情抽屉（含回调通知历史：次数/状态/每次响应码）；②「重发回调」加确认与结果反馈；③时间范围选择器默认今天
- 验收：订单详情能看到每次回调尝试记录
- 工作量 M

### P1-9 财务总览
- 现状：8 个数字平铺
- 目标：①上收入/支出/手续费改为带趋势的卡片；②新增收支结构占比环图；③导出按钮（CSV 已有后端）
- 验收：环图与数字一致；导出文件可打开
- 工作量 M

### P1-10 风控事件 / 智能体管理
- 现状：列表可用
- 目标：风控事件处置按钮按级别着色（HIGH 红显优先）；智能体创建表单分步（基础信息→作用域→确认），作用域用带说明的 checkbox 组
- 验收：HIGH 事件排序置顶；创建必填校验完整
- 工作量 M

## P1 商户门户 Portal（逐页，1 周）

### P1-11 登录/入驻流程
- 入驻表单分步条（实名 → 商户信息 → 提交）；每步独立校验；进度可视
- 验收：表单错误定位到具体字段并滚动到视野
- 工作量 M

### P1-12 应用管理（重点：密钥安全 UX）
- 创建成功后弹窗展示 appSecret：大字等宽字体 + 「复制」按钮 + 复制成功反馈 + "仅此一次"红色警示条；离开弹窗前二次确认
- 验收：复制按钮一键复制且关闭弹窗后无法再查看明文
- 工作量 S

### P1-13 订单管理
- 回调状态可视化：成功=绿点、失败=红点+重试按钮、进行中=黄点旋转图标；行内筛选 tab 化（全部/待支付/已支付/已退款）
- 验收：回调失败订单一眼可辨且可直接重发
- 工作量 S

### P1-14 收款码
- 创建固定金额码时实时预览二维码（前端生成预览）；下载 PNG 带品牌 logo
- 验收：预览与实际扫码金额一致
- 工作量 M

### P1-15 对账查询
- 日期范围快捷选项（今天/昨天/近7天/近30天）；导出后 toast 提示文件位置
- 验收：快捷选项生成的日期与业务日切（北京时间）一致
- 工作量 S

## P1 用户端 H5（逐页，1 周）

### P1-16 首页
- 现状：余额卡 + 四宫格 + 最近账单
- 目标：对齐 Revolut——余额卡增加「本月收入/支出」迷你统计；宫格图标语义微调；最近账单点击进详情（账单页锚定该条）
- 验收：余额卡数字使用等宽字体且滚动不跳动
- 工作量 M

### P1-17 转账（对齐 Wise）
- 目标：①收款人改为搜索选择（输入手机号实时联想 + 已转账联系人快捷头像）；②金额输入超大字号居中（Wise 式）；③费率/限额透明卡（显示本次扣除限额进度条）；④确认页二次确认（收款人姓名大字核对）
- 验收：转账流程 ≤ 4 步；限额进度条实时更新
- 工作量 L

### P1-18 充值
- 目标：金额快捷选择（100/500/1000 chips）+ 自定义输入；支付渠道选择卡片（当前 mock 单渠道时显示说明条）；充值结果页（成功/处理中/失败三态 + 回首页按钮）
- 验收：快捷金额点击直接填入；结果页三态正确
- 工作量 M

### P1-19 提现
- 目标：可提余额大字展示 + 「全部提现」快捷按钮；手续费实时计算展示（到账金额 = 金额 - 手续费）；进度时间线（申请→审核→代付→到账）
- 验收：手续费计算与后端一致；提现后时间线状态可查
- 工作量 M

### P1-20 红包
- 目标：拼手气红包领取动画（金额翻牌）；口令红包输入大字居中；红包详情展示领取列表（谁领了多少）
- 验收：领取交互有即时反馈动画
- 工作量 M

### P1-21 AI 助手
- 现状：已可用（需管理员创建智能体+用户授权+连接）
- 目标：①空状态引导图（三步示意图：选智能体→授权→对话）；②资金类二次确认改为卡片式（金额大字+收款人+确认/拒绝按钮）；③流式输出（接真实 LLM 后 SSE）；④会话历史列表
- 验收：二次确认卡片信息完整可拒绝；mock 模式全流程可演示
- 工作量 L

### P1-22 账单
- 目标：按日分组（日期粘性头部）；月收/支汇总条；类型图标着色（充值绿/转账蓝/提现橙）
- 验收：滚动时日期头吸顶
- 工作量 M
